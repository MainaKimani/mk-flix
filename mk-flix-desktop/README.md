# 🖥️ Blendy Play Desktop — Windows and Linux app

Electron-based desktop client for [cinejoy.pk](https://cinejoy.pk/), for
Windows (installer) and Ubuntu/Debian (`.deb`). Downloads are on
<https://blendy.mainakimani.com/#download>.

Blendy Play is a separate install from the old MK-Flix desktop app: its own
app id (`com.mainakimani.blendyplay`), Linux package (`blendy-play`) and data
folder, so it sits alongside MK-Flix and users sign in once.

## Contents

- `main.js` — app entry point: window setup, startup splash, ad/tracker
  blocking, popup and navigation rules, permissions, error screen
- `preload.js` — runs in each page before its content and applies
  `mkflix-logo.css`, so the site's logo never shows first
- `package.json` — project metadata and dev dependencies
- `adblock-hosts.txt` — ad/tracker host blocklist (shared with the Android app)
- `error.html` — shown instead of a blank window when cinejoy.pk can't load
  (network block, offline, ...), with a Retry button (shared with the Android app)
- `mkflix-account.html` — the account gate, shown at startup instead of
  cinejoy.pk. It checks the [MK-Flix backend](../../mk-flix-be) for a
  subscription (JWT kept in localStorage) and handles onboarding, M-Pesa payment
  and saving the user's CineJoy number. A signed-in user may browse without
  subscribing; playback is gated instead. The backend URL is set by the
  `MKFLIX_API_BASE` env var or `mkflix-config.json` (`apiBase`) — no editing the
  page. Shared, identical, with the Android app
- `mkflix-enforcer.js` — injected into cinejoy.pk pages: browsing is free but
  playback (a `/watch/` page) needs an active subscription, so it blocks a
  `/watch/` navigation without one and opens the paywall. Whether the user is
  subscribed is decided by the main process (`preload.js` exposes `MKFlixNative`;
  `main.js` holds the session and calls `/me/subscription` itself), so a page on
  cinejoy.pk can't fake it. Shared, identical, with the Android app
- `mkflix-menu.js` — adds a "My Subscription" item to cinejoy.pk's settings menu
  (cloned from a real item so it matches the site), opening the gate's
  subscription page — status, plan and expiry for a subscriber, or the plans for
  everyone else. The way back to payments after choosing to browse. Shared,
  identical, with the Android app
- `mkflix-lock.js` — puts a small golden padlock on each show/movie poster while
  there's no active subscription, as a hint that the content won't play (the
  enforcer does the blocking). The locks are non-interactive and disappear once
  subscribed. Shared, identical, with the Android app
- `splash.html` — startup splash, the same as the Android app's: the MK-Flix
  mark pulsing, the wordmark and a loading bar, drawn over the window while
  cinejoy.pk loads underneath, then faded out. The window opens straight
  onto it, and it stays up at least 3 s and at most 15 s. Uses `icon.png`
  and `splash-wordmark.png` (generated by `branding/make-icons.py`)
- `mkflix-footer.js` — run in every cinejoy.pk page: replaces the site's
  footer (shared with the Android app)
- `mkflix-logo.css` — draws the MK-Flix icon in place of the site's logos
  (header and video loading screen); generated by `branding/make-icons.py`
- `icon.ico`, `icon.png` — app icons for Windows and Linux; generated by
  `branding/make-icons.py` from `branding/mkflix-icon-1024.png`

## Popup policy

MK-Flix is a dedicated cinejoy.pk client, so popups are locked down: only
cinejoy.pk opens new windows. Blocklisted ad hosts and background popunders
are denied silently. Only a genuine foreground trailer link (YouTube/Vimeo)
opens in the default browser.

The same rules apply to every window the app opens, and to the page itself:
a script that tries to send the whole window to another site is stopped
(YouTube/Vimeo go to the default browser instead). Embedded players inside
the page are not affected.

## Permissions

Web content gets fullscreen and nothing else. Notifications, location,
camera, microphone and similar requests are refused automatically —
Electron would otherwise grant them all without asking.

## Build

Requires Node.js 22.12 or newer (`.nvmrc` pins 22, so `nvm use` picks it).
Node is only needed for installing and packaging; the app runs on the
Node built into Electron.

```sh
npm install
npm start               # run locally
npm run dist-win        # build dist/Blendy-Play-Setup-<version>.exe
npm run dist-linux      # build dist/Blendy-Play_<version>_amd64.deb
```

`dist-win` uses electron-builder to make a per-user NSIS installer (no
admin rights; installs under `%LOCALAPPDATA%\Programs`, with Start menu
and desktop shortcuts). On Linux it needs Wine (`sudo apt install wine`):
electron-builder runs Windows tools to stamp the exe and build the
uninstaller.

`dist-linux` uses electron-builder to make a `.deb` for Ubuntu/Debian.
It installs to `/opt/Blendy Play` with an apps-menu entry and icon;
install it with `sudo apt install ./Blendy-Play_<version>_amd64.deb` and
remove it with `sudo apt remove blendy-play`. Its install script also loads an AppArmor
profile on Ubuntu 24.04, so the installed app needs no chrome-sandbox
fix (that's only needed for `npm start` from source).

Notes:
- The installer isn't code-signed, so Windows SmartScreen warns on first
  run (More info, then Run anyway).
- `main.js` only uses Electron/Node built-ins, so the packaged app needs no
  `node_modules`. It does need `preload.js`, `mkflix-logo.css`, `mkflix-footer.js`,
  `adblock-hosts.txt`, `error.html`, `splash.html`, `splash-wordmark.png` and
  `icon.png` next to it.
- On Ubuntu 24.04 and other distros that restrict unprivileged user
  namespaces, `npm start` aborts with a SUID sandbox error. Fix it after
  each install that downloads a new Electron:

  ```sh
  sudo chown root:root node_modules/electron/dist/chrome-sandbox
  sudo chmod 4755 node_modules/electron/dist/chrome-sandbox
  ```

## Releases

Each release carries `Blendy-Play-Setup-<version>.exe` and
`Blendy-Play_<version>_amd64.deb` built with the commands above, alongside the
Android APK, on <https://blendy.mainakimani.com/#download>.
